# Игра «Камень–Ножницы–Бумага»

Веб-приложение для игры против компьютера с ведением истории раундов и подсчётом статистики.

## Запуск

1. Скачайте репозиторий: **Code → Download ZIP**, затем распакуйте архив. Либо клонируйте его через Git.
2. Откройте `index.html` в современном браузере с включённым JavaScript.
3. Нажмите «Камень», «Ножницы» или «Бумага». Каждое нажатие запускает новый раунд.

Сборка, сервер, установка пакетов и подключение к интернету для игры не требуются.

## Возможности

- Случайный выбор компьютера и определение результата по классическим правилам.
- Отображение обоих ходов и результата последнего раунда.
- Победы пользователя и компьютера, ничьи, общее количество раундов и процент побед.
- История раундов от последнего к первому с обоими ходами и результатом.
- «Сбросить статистику» обнуляет показатели и сохраняет историю.
- «Очистить историю» очищает историю и сохраняет статистику.
- «Начать заново» очищает историю, статистику и последний результат, возвращая исходный экран.

Данные хранятся в памяти текущей страницы. При перезагрузке игра начинается заново. Постоянное хранение между запусками в базовом ТЗ не требуется.

## Требования к техническому обеспечению

По ТЗ: Windows 10/11, macOS Catalina и новее или современный браузер; не менее 2 ГБ ОЗУ. Для веб-версии нужен браузер с поддержкой JavaScript. Node.js 22 нужен только для запуска тестов, для игры он не требуется.

## Структура проекта

- `index.html` — русский интерфейс игры, статистика и история.
- `style.css` — оформление и адаптация к ширине экрана.
- `script.js` — игровая логика, состояние и обновление интерфейса.
- `tests/game.test.js` — unit-тесты без сторонних зависимостей.
- `.github/workflows/ci.yml` — автоматическая проверка файлов, синтаксиса и тестов.

## Проверка качества

При установленном Node.js 22 выполните из папки проекта:

```sh
node --check script.js
node --test
```

19 unit-тестов проверяют все девять сочетаний ходов, случайный выбор, повторные ходы, нулевую статистику, подсчёт и процент побед, сохранение истории, очистку, сброс и начало заново. Также проверяются 1000 повторных одинаковых ходов.

CI запускается при push в `main` и Pull Request в `main`. Проверки доступны во вкладке [Actions](https://github.com/maksimfrolov0413-commits/rps-statistics-2026/actions).

Проверка интерфейса и надёжности описана в [протоколе тестирования](docs/testing.md).

## Проектирование базы данных (лабораторная работа №4)

Спроектирована реляционная схема SQLite в 3NF для существующей игры:

- `Choices` — три варианта хода.
- `Rounds` — раунды с датой и независимыми признаками отображения в истории и учёта в статистике.
- `Round_Choices` — выбор пользователя и компьютера в раунде; составной ключ `(round_id, participant)`.

Результат, история и статистика вычисляются представлениями `Round_Results`, `Game_History` и `Statistics`. В DDL включены первичные и внешние ключи, ограничения и индексы. SQLite пока не подключена к веб-приложению: эта лабораторная работа посвящена проектированию, а игра продолжает работать в памяти страницы.

Материалы:

- [ER-диаграмма PNG](docs/database/er_diagram.png), [SVG](docs/database/er_diagram.svg), [исходник PlantUML](docs/database/er_diagram.puml).
- [DDL схемы](database/schema.sql) и [тестовые данные](database/seed_data.sql).
- [Обоснование нормализации 1NF → 2NF → 3NF](database/normalization.md).
- [Wiki: normalization.md](https://github.com/maksimfrolov0413-commits/rps-statistics-2026/wiki/normalization.md).

Для проверки в установленном SQLite откройте **новую пустую БД** из корня репозитория:

```sh
sqlite3 rps.db
```

В консоли SQLite последовательно выполните:

```sql
.bail on
.read database/schema.sql
.read database/seed_data.sql
PRAGMA foreign_keys;
PRAGMA integrity_check;
PRAGMA foreign_key_check;
SELECT * FROM Statistics;
SELECT * FROM Game_History ORDER BY played_at DESC, round_id DESC;
```

Ожидается: `foreign_keys = 1`, `integrity_check = ok`, `foreign_key_check` без строк; в статистике 3 победы пользователя, 3 победы компьютера, 3 ничьи, 9 раундов и около 33.3333% побед. В истории — 9 раундов от последнего к первому. Скрипты рассчитаны на однократное выполнение в новой БД и не удаляют существующие таблицы.

Можно использовать SQLiteOnline из задания: выбрать SQLite и выполнить сначала содержимое `schema.sql`, затем `seed_data.sql`. Команды `.read` и `.bail` относятся только к консоли SQLite, в веб-редактор их переносить не нужно. Для каждого нового подключения включайте `PRAGMA foreign_keys = ON` до начала транзакций.
